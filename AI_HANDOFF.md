# AI Handoff

## Short Project Summary

This is a static personal portfolio/resume website for Bogdan Muntean. It is a single-page site built with `index.html`, vanilla JavaScript ES modules, committed CSS, SCSS source files, and static assets. It has no backend, no framework, no build script, and no declared npm dependencies.

## Current State Of The Project

The site appears functionally centered around `index.html` and several dynamic renderers:

- General UI behavior works through `src/main.js`.
- Skills are generated by `src/pages/AboutMe/addMySkills.js`.
- Work experience is generated from `src/data/dataWorkexperience.js`.
- Timeline entries are generated from `src/data/dataTimeline.js`.
- Portfolio cards are generated from `src/data/dataPortfolioItems.js`.
- Contact and main personal text are mostly hardcoded in `index.html`.

Important: project-detail behavior in `src/pages/Project/index.js` appears inconsistent with the current `index.html`. Phase 1 safety work now prevents it from attaching broken behavior when the legacy project-detail DOM is missing, but the feature itself remains stale/unresolved.

Important future architecture requirement: the user wants to eventually avoid editing live project code for every project content update. `PHASES_INFO.md` documents future static-compatible options such as repo-controlled JSON, Excel-to-JSON, Google Sheets-to-JSON, GitHub Actions generation, and external/cloud image workflows. None of those options are implemented yet.

## Key Files And What Each One Does

- `index.html`
  - Main browser entry point.
  - Contains all primary sections and static content.
  - Loads CSS and JS modules.
  - Defines anchors for navigation.

- `src/main.js`
  - Handles mobile menu behavior.
  - Handles back-to-top button visibility and click behavior.
  - Calls `toggleLightMode(".theme-btn")`.
  - Does not currently use `pageTransitions`; the unused import was removed during the Phase 1 safety pass.

- `src/utils/toggleLightMode.js`
  - Toggles `.light-mode` on `<html>` and `<body>`.

- `src/utils/pageTransitions.js` (removed in Phase 1)
  - Removed as dead code: an unused helper for class-based section transitions that depended on `.active-btn`, `.active`, and `data-id` conventions the current markup does not use.

- `src/utils/checkLink.js`
  - Produces active or disabled title link attributes for portfolio cards.
  - Treats empty and whitespace-only strings as disabled links.

- `src/utils/checkIcon.js`
  - Produces active or disabled icon link attributes for portfolio cards.
  - Treats empty and whitespace-only strings as disabled links.

- `src/pages/AboutMe/index.js`
  - Coordinates rendering for work experience and timeline.
  - Imports `addMySkills.js` for side-effect skill rendering.

- `src/pages/AboutMe/addMySkills.js`
  - Holds skill data internally.
  - Renders skill categories into `#skills-list`.
  - No-ops if `#skills-list` is missing.

- `src/pages/AboutMe/addWorkexperienceItems.js`
  - Appends work experience items into `.experience-container`.
  - Returns safely if the requested container is missing.

- `src/pages/AboutMe/WorkexperienceItem.js`
  - Creates individual work experience DOM elements.

- `src/pages/AboutMe/addTimelineItems.js`
  - Appends timeline items into `.timeline-container`.
  - Returns safely if the requested container is missing.

- `src/pages/AboutMe/TimelineItem.js`
  - Creates individual timeline DOM elements.

- `src/pages/Portfolio/index.js`
  - Renders portfolio cards into `.portfolio-list`.

- `src/pages/Portfolio/addPortfolioItems.js`
  - Iterates portfolio data and appends portfolio item elements.
  - Returns safely if the requested container is missing.

- `src/pages/Portfolio/PortfolioItem.js`
  - Creates portfolio card DOM elements from title, image, live link, and repo link.

- `src/pages/Project/index.js`
  - Intended project-detail script.
  - Currently expects DOM that does not exist in `index.html`.
  - Guarded in Phase 1 so it does not attach project-detail click behavior unless `.active`, `#project`, and `#portfolio` exist.

- `src/data/dataPortfolioItems.js`
  - Portfolio project data and commented-out older project data.

- `src/data/dataTimeline.js`
  - Education/training timeline data.

- `src/data/dataWorkexperience.js`
  - Work experience data.

- `src/assets/variables.scss`
  - Theme variables, responsive variables, and SCSS mixins.

- `src/assets/style.scss`
  - Global layout, header/nav, mobile menu, theme button, back-to-top button, shared titles.

- `src/pages/*/*.scss`
  - Section-specific styling.

## Important Conventions Used

- Static sections are identified by anchor IDs ending in `-section`, such as `#portfolio-section`.
- Dynamic render targets are:
  - `#skills-list`
  - `.experience-container`
  - `.timeline-container`
  - `.portfolio-list`
- JavaScript renderers use `document.createElement()` and `innerHTML`, then append nodes into existing containers.
- Data files export arrays with named objects.
- Portfolio items are rendered from object fields:
  - `title`
  - `description`
  - `imageLink`
  - `liveLink`
  - `repoLink`
  - `photo`
  - `video`
- Styling uses CSS custom properties from `src/assets/variables.scss`.
- The loaded runtime CSS files are `.css`, not `.scss`.
- Light mode depends on a `.light-mode` class on `<html>` and `<body>`.

## How To Safely Continue Development

1. Keep changes documentation-only unless explicitly asked to change app behavior.
2. If changing content:
   - Update static text/contact/download markup in `index.html`.
   - Update portfolio data in `src/data/dataPortfolioItems.js`.
   - Update work experience data in `src/data/dataWorkexperience.js`.
   - Update timeline data in `src/data/dataTimeline.js`.
   - Update skills in `src/pages/AboutMe/addMySkills.js`.
3. If changing styles:
   - Edit the relevant `.scss` source file.
   - Also ensure the corresponding `.css` file is regenerated, because `index.html` loads CSS directly.
   - No Sass compile command is defined, so ask/check before choosing a compiler workflow.
4. If changing JavaScript:
   - Preserve the existing module script loading in `index.html`.
   - Check DOM element existence before attaching listeners.
   - Be careful with project-detail behavior. `Project/index.js` currently loads after `Portfolio/index.js`, but the current page still lacks the legacy `.active`, `#project`, and `#portfolio` elements needed for the intended detail flow.
5. If adding dependencies:
   - Update `package.json` and `package-lock.json`.
   - Add documented install/run/build scripts if needed.

## What Not To Change Without Checking First

- Do not rename section IDs in `index.html` without updating both desktop and mobile navigation anchors.
- Do not move `src/assets/docs/CV_Bogdan_Muntean.pdf` or `src/assets/docs/Recommendation_Letters_Bogdan_Muntean.pdf` without updating download links.
- Do not delete icons in `src/assets/icons` without checking `src/pages/AboutMe/addMySkills.js`.
